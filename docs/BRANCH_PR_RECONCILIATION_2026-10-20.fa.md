۲. **فقط با اجازه صریح مالک برای تغییر QA و شروع ساخت اندروید**، بررسی شود remote QA هنوز همان `53e4206…` و جد نامزد نهایی است؛ سپس همان شاخه QA تا نامزد نهایی fast-forward شود. این کار force، rebase یا زنجیره ادغام جداگانه PRهای قدیمی نمی‌خواهد و PR18 همان درخواست واحد می‌ماند.

۳. به‌روزرسانی QA، رویداد PR18 را فعال می‌کند و طبق workflow موجود باید regression و **هر دو APK مشتری و متخصص** را خودکار راه بیندازد. بنابراین حتی بدون اجرای مستقیم Gradle، این اقدام ساخت اندروید را شروع می‌کند؛ در توقف فعلی مجاز نیست. شروع و موفقیت واقعی فقط پس از مشاهده اجرای مربوط به head نهایی گزارش شود.

۴. پس از بررسی و تست head نهایی و مجوز ادغام، PR18 واقعاً وارد پیش‌فرض شود. **فقط بعد از آن** PRهای #9، #10، #12 و #17 به‌عنوان پوشش‌داده‌شده/جایگزین بسته شوند. شاخه‌هایشان برای بازیابی حفظ شوند. PR15 همچنان Draft و تعویقی بماند.

## تشخیص آنچه واقعاً اجرا شده است

از روی این ممیزی نمی‌توان با قطعیت گفت صفحه‌ای که قبلاً روی دسکتاپ یا گوشی باز بوده از کدام شاخه ساخته شده است. نام فایل APK، Git فعلی یا سرور تازه این موضوع را ثابت نمی‌کند. نشان جدید «نسخه اجرا» یک snapshot از منبع زمان شروع یا bundle را در خود خروجی نگه می‌دارد: شاخه، شناسه کامل و وجود تغییرات ثبت‌نشده؛ نبود مدرک به‌صورت «نامشخص» اعلام می‌شود. خروجی‌های قدیمی با تغییر Git به خروجی تازه تبدیل نمی‌شوند. دستور restart، پاکسازی cache و محدودیت Fast Refresh در [SOURCE_IDENTITY.md](SOURCE_IDENTITY.md) آمده است.

## دامنه و محدودیت شاهد

فهرست شاخه‌ها با Git HTTPS و PRها از صفحات زنده عمومی گیت‌هاب خوانده شد. API گیت‌هاب در شبکه این جلسه پاسخ 403 می‌داد؛ دسترسی Git معادل اختیار تغییر PR نیست. وضعیت mergeability، حفاظت شاخه و تأییدهای لازم از این نما معلوم نیست. **هیچ تغییر واقعی در وضعیت PRها، QA، پیش‌فرض یا remote refs انجام نشد؛ هیچ شاخه‌ای حذف نشد و در این زیرکار هیچ تست محصول یا APK ساخته نشد.**

شواهد محلی تکمیلی این جلسه در `/workspace/reports/paksho-supervision-20261020/branch-reconciliation/` شامل `branch-metrics.json`، `PR_INVENTORY.json` و `pr-live-metadata.json` است. دوام این مسیر بیرون از محیط ابری مستقل تأیید نشده؛ این سند خلاصه قابل نگهداری داخل مخزن است.
